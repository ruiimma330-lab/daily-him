# idol-chat 产品规划 v2

> 文档日期：2026-10-29（Asia/Shanghai）  
> 状态：已确认方向，待用户确认本文档后从阶段 0 动手  
> 范围：自用 AI 爱豆分身聊天（边伯贤风格人设）；**不含学语言**

---

## 1. 目标与非目标

### 1.1 目标

做一个像 KakaoTalk 的 AI 爱豆分身聊天产品：以**语音气泡**为主交流，服务端持久保存聊天与记忆，有正式账号，关系会从陌生变熟悉，并逐步补上迷你朋友圈与产品壳，最终迁到微信小程序，方便手机随时用。

当前线上地址：https://dailyhim.cn

### 1.2 非目标（明确不做 / 延后）

| 项 | 说明 |
| --- | --- |
| 学语言模式 | 不教韩语、不纠错、不做课程；自然聊天即可 |
| 主动推送 / 订阅消息 | 暂不做早安晚安推送、免打扰推送等 |
| 「我们的瞬间」相册 | 暂不做 |
| 实时通话 | 暂不做（语音气泡 ≠ 实时通话） |
| UGC / 多角色广场 | 暂不做开放角色广场、用户投稿人设 |
| 抽卡 / 礼物商城玩法 | 充值页先做界面与流程，复杂商业化玩法后议 |
| 克隆真人公开语音 | 禁止；仅使用用户**自己**克隆的音色 |
| 真实爱豆照片作头像 | 禁止；继续用非真人素材 |

## 2. 产品现状（2026-10-29）

### 2.1 已有能力

- KakaoTalk 风格网页聊天；边伯贤风格人设（公开可核实事实 + 标注原创口头禅）
- LLM：DeepSeek；TTS：ElevenLabs（用户自克隆音色 `zG6oPYFpVjyTj1zUmVTY`，模型 `eleven_v3`）
- 已从 Render 免费版迁移到香港服务器：https://dailyhim.cn
- 当前身份门：环境变量 `APP_PASSWORD` + 签名 Cookie（全站共享一份密码，**不是**每人账号）
- 密钥仅通过环境变量注入（`DEEPSEEK_CHAT_API_KEY`、`ELEVENLABS_API_KEY` 等），不写进仓库

### 2.2 已知痛点

1. **聊天记录只存在浏览器 `localStorage`**：换浏览器、微信内置浏览器、清缓存后打开即「全新对话」；服务器未存会话。
2. **回复形态不自然**：常固定「两句文字气泡 + 一条语音」，不像真人聊天（有时一句、有时两三句）。
3. **TTS / LLM 曾在 Render 失败**：环境变量粘贴时混入空格、换行等脏字符导致 key 长度异常；已加安全日志（只记类型/长度/是否含非法字符，不记 key 本身）。
4. **无正式注册登录**：无法按用户隔离数据，也无法换设备续聊。

## 3. 已定产品方向（用户确认）

1. **语音气泡为主**：默认不堆文字气泡；可展开查看**韩语原文 + 中文翻译**（音色与样本数据可后补）。
2. **聊天记录必须服务端持久**；并建立正式账号体系。
3. **登录第一版：用户名 + 密码**；邮箱 / 手机号以后再加。
4. **亲密度 + 相识天数**：陌生期可婉拒部分请求；熟悉后放开深度与话题。
5. **暂不做主动推送**。
6. **迷你朋友圈**：传递艺人近期公开资讯与重大活动预告（通稿 / 官宣口径），第一人称消息流；不是闲聊流水账。
7. **场景按钮**（睡前 / 好累 / 瞎扯等）**内置但不急上**。
8. **不做**「我们的瞬间」相册。
9. **产品壳**：封面页 → 加载页 → 选爱豆 → 给爱豆起昵称、他怎么叫你、用户基本信息 → **充值页**（先 UI / 流程）。
10. **最终迁微信小程序**（网页版核心稳后再迁，少返工）。

补充约定（同日确认）：

- 同一账号跨设备看到同一份聊天记录与记忆。
- 「清空对话」需同步删除服务端对应数据。
- 回复条数自然化：不固定两句；与语音气泡改造同阶段处理。

## 4. 分阶段路线图（按优先级）

> 顺序已按用户痛点重排：**先账号与持久化 → 关系系统 → 语音 UI → 朋友圈 → 产品壳 → 场景 → 小程序**。

### 阶段 0｜准备：账号与持久化（最高优先）

**目标**  
解决「一打开就变成新聊天」；用**用户名 + 密码**建立每人独立身份；聊天与记忆存服务端。

**要做的功能点**

- 注册 / 登录 / 登出（用户名 + 密码；密码哈希存储，不明文）
- 会话 Cookie / Token：登录态与账号绑定（可逐步替换或并存现有 `APP_PASSWORD` 门；上线账号后共享密码门应退役或仅作运维后门，需再确认）
- 服务端持久化：
  - 聊天 history（按 `userId` + 角色/会话）
  - 人设侧长期记忆（称呼、约定、偏好等结构化字段 + 必要摘要）
- 打开 App 时从服务端拉取历史并渲染
- 「清空对话」API：删服务端记录并清空前端
- 免费云数据库接入（见 §5）；**不要**只写 Render 本地磁盘（免费实例重启会丢）
- 基础限流：注册 / 登录防刷

**验收标准**

- 同一用户名登录后，刷新、换浏览器、换设备仍能看到完整历史
- 未登录无法读写他人会话
- 清空对话后服务端与前端均无该会话消息
- 密钥仍仅来自环境变量；仓库与日志无明文密码 / API key
- Render 重启后历史仍在（云库验证）

**依赖**

- 选定并开通云数据库（Turso / 等价免费 SQLite 或 Postgres）
- Render 增加数据库相关环境变量（连接串等）

**风险**

- Render 免费盘不可靠 → 必须云库
- 用户名枚举 / 撞库 → 注册登录限流 + 通用错误文案
- 从 `APP_PASSWORD` 迁到账号体系时旧访客无历史可迁（可接受：当前本就无服务端历史）

### 阶段 1｜关系系统（相识天数 + 亲密度）

**目标**  
关系「看得见、会变」：从陌生到熟悉，影响语气与是否答应某些请求。

**要做的功能点**

- 相识天数：自首次成功对话或注册绑定角色日起算
- 亲密度分数 / 等级（规则需可配置：聊天天数、轮次等；避免纯氪金）
- 人设规则挂钩：
  - **陌生**：可婉拒部分请求（过界私密、过火暧昧等），语气更拘谨
  - **熟悉**：更放松、更深一点但仍不越界（既有「暧昧但不越界」红线不变）
- UI：轻量展示相识天数（亲密度条可极简；用户曾表示「轻量即可」，避免做成重度养成数值墙）

**验收标准**

- 新号前 N 天 / 低亲密度时，对指定类请求出现婉拒或降调回复（可测用例）
- 达到熟悉阈值后，同类请求不再机械婉拒
- 天数与亲密度跨设备一致（服务端存）

**依赖**

- 阶段 0 账号与服务端存储

**风险**

- 规则过硬像游戏任务 → 提示词 + 少量硬规则结合，避免纯关键词墙
- 与「暧昧不越界 / 承认 AI」红线冲突 → 关系升级**不**等于变成「真男友」叙事

---

### 阶段 2｜语音气泡 UI + 回复条数自然化

**目标**  
交互像发语音：默认一条语音；可展开韩语 + 中文；回复长度像真人，不固定两句文字。

**要做的功能点**

- 聊天气泡改版：AI 侧以**语音气泡**为主（播放 / 暂停、时长）
- 展开面板：韩语原文 + 中文翻译（翻译可 LLM 附带或独立一步；缓存以免重复扣费）
- 调整 LLM 输出约束：取消「几乎总是两句」的暗示；允许 1～3 句量级，多数时候偏短
- 服务端：TTS 失败时的明确提示（不假装已发送语音）；继续保留安全失败日志
- 前端：历史中的语音 URL / 缓存策略与登录用户绑定

**验收标准**

- 用户一眼看到的是语音，不是两行字 + 一条音
- 展开后可见韩文与中文；收起后界面干净
- 连续多轮回复句数有变化，不再稳定「刚好两句文字」
- TTS 失败时有可读错误态，不丢整段会话

**依赖**

- 阶段 0（历史里要能存语音元数据与文本）
- ElevenLabs / DeepSeek 环境变量正确（无脏字符）

**风险**

- 每次必 TTS → 费用与延迟上升；需缓存命中与短回复策略
- 翻译质量不稳定 → 可标「参考翻译」
- 微信内置浏览器音视频策略 → 阶段 6 再专项测

---

### 阶段 3｜迷你朋友圈

**目标**  
把朋友圈做成「艺人消息通道」：近况资讯、重大活动预告/速递，增强非单聊粘性。

**要做的功能点**

- 动态列表页 / Tab：文案 +（可选）配图；条目带类型标签（近况 / 预告 / 活动）
- 素材策略：近几天**真实公开**新闻 / 通稿 / 官宣，改写成第一人称短讯；可附官方外链
- 更新频率：每天少量（如 1～3 条），可预生成或定时任务
- 与亲密度弱关联（可选：仅熟悉后可见部分动态——若做需写清规则）

**验收标准**

- 能刷到若干条近况或活动预告，文风符合人设，类型可读
- 不出现伪造未公开隐私或未核实八卦当「事实」
- 动态有时间戳；刷新不重复刷屏异常

**依赖**

- 阶段 0；公开资讯源或人工精选池（自动化抓取需合规与稳定性评估）

**风险**

- 资讯版权与肖像 → 只用文字摘要 + 非真人图 / 抽象图，避免盗用新闻原图
- 自动化抓取易碎 → 第一版可「精选池 + 半自动」

---

### 阶段 4｜产品壳（封面 / 加载 / 选人 / 昵称 / 资料 / 充值）

**目标**  
有完整 App 感觉的壳，为小程序与后续商业化铺路；充值先做 UI 与流程骨架。

**要做的功能点**

- 封面页（品牌 / 爱豆分身氛围）
- 加载界面（含冷启动、Render 休眠唤醒时可友好提示「醒来中」）
- 选择人物（当前可先单人「边伯贤风格」占位，结构支持多人）
- 引导：给爱豆昵称、他怎么称呼用户、用户基本信息（写入服务端档案，供人设使用）
- 充值页 UI：套餐展示、余额/次数展示、购买按钮流程（真实支付可后接；标明虚拟商品与自用性质）

**验收标准**

- 新用户路径：封面 → 加载 →（登录/注册）→ 选人 / 填昵称资料 → 进入聊天，无断链
- 昵称与「他怎么叫你」进入对话后生效
- 充值页可浏览；未接支付前点击有明确「即将开通」或测试态，不误扣款

**依赖**

- 阶段 0 账号与用户资料表
- 设计稿可先用简洁 Web UI，不阻塞功能

**风险**

- 过早接支付增加合规与退款复杂度 → UI 与支付网关解耦
- 多角色未就绪时选人页勿过度承诺

---

### 阶段 5｜场景按钮（内置，不急）

**目标**  
轻场景入口当彩蛋，丰富体验但不抢主路径。

**要做的功能点**

- 内置若干场景：如睡前、好累、瞎扯等
- 点击后注入场景提示或跳转预设开场，仍走同一套语音气泡与关系规则
- 默认折叠 / 次级入口，避免占满主聊天屏

**验收标准**

- 场景可触发且回复符合该场景语气
- 不影响普通自由聊
- 与亲密度规则不冲突

**依赖**

- 阶段 2 语音气泡体验稳定为佳

**风险**

- 场景过多稀释人设 → 先 3 个以内

---

### 阶段 6｜微信小程序迁移

**目标**  
在网页核心（账号、历史、关系、语音气泡）稳定后，迁到微信小程序，便于国内手机使用。

**要做的功能点 / 要点**

- 小程序前端重写或用合适框架复用 API；后端尽量保持同一套 REST
- **登录**：微信登录与现有「用户名密码」账号的绑定策略（需单独设计；可「微信身份绑定已有用户名」）
- **存储**：继续用同一云数据库；媒体（语音文件）存对象存储或带鉴权的临时 URL
- **订阅消息 / 主动推送**：按已定方向**暂不做**
- 合规：小程序类目、隐私协议、用户协议；界面标明 AI / 非本人
- 体验版可先自用；正式上架另开合规清单
- 域名与 HTTPS（小程序要求）；若用国内服务器需另行评估 ICP 等

**验收标准**

- 体验版：登录（或绑定）后能聊天、听语音、看历史、亲密度一致
- 与网页版数据打通（同一账号）
- 无未授权主动推送

**依赖**

- 阶段 0～2 至少完成；4 的壳可小程序侧重做视觉
- 微信公众平台账号与类目资质

**风险**

- 语音播放、后台限制与审核素材（爱豆形象）敏感 → 素材与文案需自用 / AI 分身表述清晰
- 微信登录与用户名体系双轨复杂度

## 5. 技术选型建议（简短）

| 层 | 建议 |
| --- | --- |
| 运行时 | 保持现有 **Node.js** 服务（`server.js` + `public/`） |
| LLM / TTS | DeepSeek + ElevenLabs；模型与 voiceId 仍由 `config.json` / 环境配置 |
| 账号 | 用户名 + 密码（bcrypt/argon2 哈希）；Session 或 JWT + HttpOnly Cookie |
| 数据 | **免费云 SQLite（推荐 Turso）** 或等价托管 Postgres；表：users、sessions、messages、memories、profiles、relationship |
| 文件 | 语音缓存：对象存储或短期本地 + CDN；注意 Render 本地不可持久 |
| 密钥 | **仅环境变量**（Render Dashboard）；禁止写入仓库、日志、前端 |
| 部署 | 继续 Render 免费试跑；国内访问差再评估国内机房 / 小程序后端 |

## 阶段 1 实现说明（2026-10-29）

**亲密度公式**（`config.json` → `relationship` 可调）：每个有聊天的自然日（Asia/Shanghai）+6 分；每轮对话 +1 分，每天最多计 8 分。即每天最多 14 分。

| 档位 | 分数 | 相识天数（含当天）|
|---|---|---|
| 陌生 처음 | 0 | 1 |
| 朋友 친구 | ≥15 | ≥2 |
| 好友 절친 | ≥45 | ≥4 |
| 暧昧 썸 | ≥90 | ≥6 |

每天聊 8 轮以上：第 2 天朋友、第 4 天好友、第 7 天暧昧。相识天数门槛防止一天刷到顶。

**火花规则**：当天聊过 → 🔥 亮；今天还没聊 → 正常显示等待；断 1 天 → 火花变灰，再聊一句恢复并继续累计；断 2 天及以上 → 熄灭，下次聊天从 1 重新计数。亲密度不会因断聊下降。

**接口**：`GET /api/relationship`；`/api/chat` 返回 `relationship`（含 `tierUp`）；`DELETE /api/relationship`（body `{"confirm":"RESET"}`，前端暂未放按钮）。清空对话不重置关系。

**人设**：`persona/system_prompt.md` 末尾分档章节，服务端只注入当前档；旧版备份 `system_prompt_v5_before_relationship.md`。
